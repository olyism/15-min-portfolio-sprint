# Design System: Portfolio Sprint

## Overview

The shared portfolio shell remains restrained and consistent. Seven case studies now own independent visual systems, each supported by an original generated product screenshot, its own typography, six scoped colour roles and a nested design-system route. This replaces the original coded showcase-artifact presentation. Small local interaction exercises remain separate from the image-based artwork.

Canonical identity data is in content/project-worlds.json. Token values come from app/tokens.css; scoped aliases and presentation rules come from app/project-worlds.css. The user requested this expansion and previously delegated creative choices and self-approval. The current plan is docs/PROJECT-WORLDS-PLAN.md.

## Colors

Each project defines ground, reading surface, primary ink, secondary ink, action and selected-surface roles. All project colours use light-dark pairs. Relay and Afterhours intentionally use a dark identity under both preferences. The other five adapt between lighter and darker reading surfaces. A screenshot retains its authored appearance and is never inverted or recoloured by the theme.

Data-world aliases map each scope to the corresponding central role tokens. Text selection and focus use the scoped action colour. The shared header and footer retain the portfolio tokens. Palette values above are exact source values, not sampled claims about the generated screenshots.

## Typography

Each case study's display face and body face are recorded above. Fonts are self-hosted from public/fonts/ with adjacent OFL licences and swap loading. Shell typography preserves the existing system stack. DM Sans remains the quiet utility face for Formwork, Common Ground and Afterhours. Sora and Literata remain registered as legacy foundation specimens; they no longer define these project identities.

Fluid brand titles, technical titles, editorial titles and type samples use the central text-world tokens. Inter in Relay is an intentional response to the user's request for a slick Linear-like product language. Artwork typography is generated raster content; the live page uses the corresponding self-hosted font family without claiming pixel-identical glyph rendering.

## Layout

Case-study pages begin with project-level navigation between the case study and its system. Existing story sections remain. Headers vary by identity: Relay's narrow operations statement, Tandem's centred friendly proposition, Formwork's technical title, Common Ground's editorial headline, Plainly's service heading, Waypoint's decisive strategy typography and Afterhours' cinematic display.

Generated images render at their natural aspect ratio, with no HTML app reconstruction or decorative overlays. Caption and full-resolution links sit outside the artwork. Design-system pages document typography, paired colours, foundations, the full interface image, principles and product references. Mobile rules wrap navigation, reduce colour grids and stack foundation and principle layouts. Reading measures and spacing live in central tokens.

## Elevation & Depth

Project narrative surfaces use tonal separation and restrained hairlines. Gallery cards retain the shell's existing soft hover elevation. Any photographic depth or UI elevation inside a screenshot belongs to the generated asset, not a CSS reconstruction. Avoid adding extra glass, gradients or nested panels around the images.

## Shapes

World-sharp corners serve Relay, Formwork, Common Ground, Waypoint and Afterhours; world-soft serves Tandem and Plainly. The shared card radius remains part of the gallery shell. Text, corners and padding should be edited through tokens rather than arbitrary project CSS values.

## Components

ProjectVisual is a server-rendered image wrapper using metadata from content/project-worlds.json. ProjectIdentityNav links each case study to its nested system. The nested design-system page reads its actual palette from the token loader. No screenshot control is presented as a working production feature.

ProjectPlayground retains the separate local exercises: policy fixtures, shift request/withdrawal, a component workbench, synthetic evidence navigation, content comparison, illustrative capacity choice and sample seat selection. These use native controls, focus states and status messages and do not connect to production services.

Generated image briefs are in content/artifacts/project-image-briefs.json. Product-reference URLs and specific inspiration notes are in the project identity data and are displayed on each system page. Original artwork has no third-party branding and is not represented as a client's shipped product.

## Do's and Don'ts

- Use the project's scoped tokens and self-hosted type family; preserve the shared shell.
- Preserve image aspect ratio and provide a useful alt description and full-resolution route.
- Keep generated imagery, synthetic evidence and local-demo limits clear outside the artwork.
- Treat reference products as inspiration, not clients or affiliations.
- Keep consequential action controls separate from static screenshots.
- Check phone and desktop layouts under both preferences before claiming rendered QA.
- Do not restore the previous coded app specimens or fictional-concept stamps over the artwork.

Verification record: the production Webpack build, TypeScript and lint passed; all fourteen project/system routes returned successful responses, and all 84 tested project token contrast combinations met the 4.5:1 threshold. Browser access was subsequently approved and verification completed: all fourteen case-study/system pages were checked at desktop and phone widths in both themes (56 loaded-image, overflow and capture checks), plus narrow 320px reflow checks on all fourteen pages. Project navigation, menu/theme controls, keyboard focus and full-resolution image access were exercised. Independent review returned ship with no material fixes after inspecting fourteen representative captures and validating metadata for the other forty-two. External reference fidelity remains unscored.

## Relay refinement · November 2026

Relay adds a generated pearlescent R mark, five narrative UI images and a scripted incident workspace. The workspace pairs a numbered state graph and cited evidence with a separate agent console. Lavender marks the current state, mint marks completed evidence and amber marks a paused or rejected run. Sheen stays inside panels and borders; no perpetual shimmer or animated glow is used. New roles are `relay-positive`, `relay-warning`, `relay-sheen` and `shadow-relay-edge` in `app/tokens.css`. All interaction events are synthetic and local.

The portfolio header uses `header-glass`, `header-sheen` and `blur-header`, with opaque fallback and primary ink for readable navigation in both themes. The Writing navigation label and resource index title are now Resources; existing `/blog` addresses stay valid. The Relay refinement brief and validation scope are recorded in `docs/RELAY-REFINEMENT.md`.
