# Independent project identities

## User direction
Each case study owns an independent brand and a nested `/projects/<slug>/design-system` page. Replace the hand-coded visual specimens with generated product screenshots, informed by real product research. Remove fictional-concept stamps from the artwork. Keep one clear disclosure in the narrative and preserve working demos as separate optional exercises.

## Approach
1. Inspect real product references and capture their surfaces.
2. Generate one original screenshot direction for each of the seven existing projects; use references for relevant patterns, not vendor logos or claimed work.
3. Store images in public/images/projects/ and briefs, image descriptions, principles and reference links in content/.
4. Give each project a distinct font, palette, visual rhythm and narrative treatment. Central values remain in app/tokens.css.
5. Add the seven nested design-system routes with type specimens, paired colour swatches, foundations, interface preview, principles and sources. Link them from case studies, global design-system index, sitemap and AI site map.
6. Verify all routes, image loading, mobile and desktop layouts, themes, build and lint. Update design documentation by merging the new project-world definitions into the existing record, as authorized by the requested design-system changes.
